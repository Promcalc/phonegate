# Telegram-бот: привязка номера через PhoneGate

Дополнение к [tz.md](tz.md). Описывает сценарий, когда бот не знает номер
пользователя заранее и узнаёт его по входящей SMS с кодовым словом.

## 1. Что даёт Telegram

| Способ | Что получает бот | Ограничения |
|---|---|---|
| Кнопка «Поделиться контактом» (`request_contact`) | Номер телефона аккаунта Telegram | Только личный чат; пользователь должен нажать кнопку; номер — тот, что привязан к Telegram |
| `Telegram.WebApp` / `initData` | `user.id`, имя, язык | Номера телефона нет |
| Telegram Login Widget | `id`, имя, фото | Номера телефона нет |
| Telegram Passport | Телефон, если пользователь разрешил | Сложная интеграция, избыточно для бота |
| **Code-first через SMS** | Номер, с которого отправлена SMS | Пользователь тратит SMS; нужен шлюз с номером |

Вывод: если нужно подтвердить именно номер аккаунта Telegram — проще и дешевле
`request_contact`. Если нужен **любой** номер (рабочий, второй, номер без Telegram)
или кнопка недоступна — используем code-first.

При `request_contact` бот обязан проверить, что пришла именно карточка отправителя:
`message.contact.user_id == message.from.id`. Иначе пользователь может прислать
контакт другого человека, и это будет чужой номер.

## 2. Сценарий code-first

```
Пользователь            Бот                    PhoneGate              Шлюз
     |                    |                        |                    |
     |-- /start --------->|                        |                    |
     |                    |-- POST /verifications  |                    |
     |                    |   mode=code_first ---->|                    |
     |                    |<-- gateway_number, ----|                    |
     |                    |    code, ttl           |                    |
     |<-- «Отправьте SMS  |                        |                    |
     |    с кодом K7M4... |                        |                    |
     |    на +7900...»    |                        |                    |
     |                    |                        |                    |
     |-- SMS с кодом ------------------------------------------------>  |
     |                    |                        |<-- exchange: SMS --|
     |                    |                        |-- match по коду -->|
     |                    |<-- webhook: verified --|                    |
     |                    |    phone=+7900...      |                    |
     |<-- «Номер +7900... |                        |                    |
     |    привязан»       |                        |                    |
```

1. Пользователь запускает бота и выбирает «Привязать номер».
2. Бот (его backend) вызывает `POST /api/v1/verifications` с `mode=code_first`.
   Номер пользователя **не передаётся** — его ещё никто не знает.
3. PhoneGate выбирает номер шлюза из пула арендатора, генерирует код и возвращает
   `id`, `gateway_number`, `code`, `expires_at` и `links` (ссылки и QR).
4. Бот отправляет в чат код в `<code>...</code>`, инструкцию и inline-кнопку
   «Открыть страницу» с `links.page_url`. На странице есть кнопки «Отправить SMS»,
   «Позвонить» и копирование; QR — для десктопа.
5. Пользователь отправляет SMS со своего телефона.
6. Шлюз принимает SMS и передаёт её в очередном обмене.
7. PhoneGate находит активную заявку по коду, извлекает номер отправителя,
   помечает заявку `verified` и отправляет вебхук боту (или бот узнаёт статус опросом).
8. Бот проверяет, что `metadata.telegram_user_id` совпадает с тем пользователем,
   который запрашивал код, и привязывает номер к аккаунту.

## 3. API

### 3.1. Создание заявки

`POST /api/v1/verifications`

```json
{
  "mode": "code_first",
  "method": "sms",
  "purpose": "telegram_bind",
  "locale": "ru",
  "ttl_seconds": 600,
  "metadata": {
    "telegram_user_id": 123456789,
    "telegram_chat_id": 123456789
  }
}
```

Ответ `201`:

```json
{
  "id": "vrf_01JABCDEFGHJKMNPQRSTVWXYZ0",
  "mode": "code_first",
  "status": "pending",
  "method": "sms",
  "phone": null,
  "gateway_number": "+79005550001",
  "code": "K7M4Q9PX",
  "instructions": "Отправьте SMS с текстом K7M4Q9PX на номер +79005550001",
  "created_at": "2026-10-21T12:00:00Z",
  "expires_at": "2026-10-21T12:10:00Z",
  "poll_after_ms": 3000,
  "links": {
    "sms_uri": "sms:+79005550001?body=K7M4Q9PX",
    "sms_uri_ios": "sms:+79005550001&body=K7M4Q9PX",
    "tel_uri": null,
    "page_url": "https://auth.example.com/v/vt_01JABCDEFGHJKMNPQRSTVWXYZ0",
    "qr_url": "https://auth.example.com/v/vt_01JABCDEFGHJKMNPQRSTVWXYZ0/qr.png"
  }
}
```

Правила:

- `mode=code_first` допускает только `method=sms`; звонок не может передать код.
- `phone` в запросе не передаётся; если передан — `400 phone_not_allowed`.
- Код генерирует **PhoneGate**, не бот. Это гарантирует уникальность и энтропию.
- Код одноразовый, живёт `ttl_seconds` (по умолчанию 600 с, максимум 900 с).
- Код уникален среди активных SMS-заявок на том же номере шлюза; при коллизии
  генерируется новый. На одном номере шлюза могут одновременно существовать разные
  SMS-коды разных заявок.
- В ответе код возвращается один раз; в БД хранится только хэш.
- Формат кода задаётся конфигом: `alnum` (8 символов), `digits` (8 цифр) или
  `words` (4 слова из словаря). Во всех случаях код генерирует сервер, а не бот.

### 3.2. Статус

`GET /api/v1/verifications/{id}`

Пока SMS не пришла:

```json
{
  "id": "vrf_01J...",
  "mode": "code_first",
  "status": "pending",
  "phone": null,
  "gateway_number": "+79005550001",
  "expires_at": "2026-10-21T12:10:00Z"
}
```

После совпадения:

```json
{
  "id": "vrf_01J...",
  "mode": "code_first",
  "status": "verified",
  "phone": "+79001234567",
  "gateway_number": "+79005550001",
  "verified_at": "2026-10-21T12:01:17Z"
}
```

`phone` появляется только после подтверждения. До этого поля нет или оно `null`.

### 3.3. Вебхук

```json
{
  "event": "verification.verified",
  "delivery_id": "whd_01J...",
  "verification": {
    "id": "vrf_01J...",
    "mode": "code_first",
    "status": "verified",
    "phone": "+79001234567",
    "gateway_number": "+79005550001",
    "verified_at": "2026-10-21T12:01:17Z",
    "metadata": {
      "telegram_user_id": 123456789
    }
  }
}
```

Бот обязан проверить подпись вебхука и сверить `telegram_user_id` с тем, кому
выдавался код. Нельзя доверять только `verification_id` из тела.

Ссылки `links` приходят только в ответе на создание/повтор; бот должен сохранить их
до истечения заявки. В `GET` их нет, потому что SMS-ссылки содержат одноразовый код.

### 3.4. Страница и кнопки

Telegram не гарантирует открытие `sms:`/`tel:` из inline-кнопок: `url` официально
рассчитан на HTTP/HTTPS и `tg://`. Поэтому бот не делает кнопку «Позвонить» или
«Отправить SMS» напрямую, а ведёт на `page_url`:

```
[Открыть страницу]  ->  https://auth.example.com/v/<token>
```

На странице:

- «Отправить SMS» — `sms_uri` (Android) или `sms_uri_ios` (iOS): номер и текст уже
  заполнены, пользователь нажимает только «Отправить»;
- «Позвонить» — `tel_uri`: открывается dialer, пользователь нажимает вызов;
- «Скопировать код» и «Скопировать номер» — если приложение не подставило текст;
- QR-код — для десктопа: сканировать телефоном, откроется SMS/звонок;
- статус — «Ожидаем SMS/звонок», затем «Готово».

В самом чате код показывается в `<code>K7M4Q9PX</code>` (отправка с `parse_mode=HTML`):
в Telegram по нажатию он копируется. Кнопка «Я отправил» только запускает опрос
статуса, но не подтверждает номер. QR можно отправить отдельным сообщением
(`sendPhoto` с `qr_url`), если пользователь читает бота на компьютере.

Ограничения:

- В Telegram WebView `sms:`/`tel:` могут не открыться; страница показывает
  «Открыть в браузере» и кнопки копирования.
- На iOS текст SMS может не подставиться; используйте `sms_uri_ios` и копирование.
- Переход по ссылке или нажатие «Отправить» не считается подтверждением: только
  событие от шлюза меняет статус.

## 4. Алгоритм бота

Псевдокод:

```text
on "Привязать номер" from user U:
    if U has active pending code:
        reuse it (не генерировать новый)
    else:
        r = POST /verifications {mode: code_first, metadata: {telegram_user_id: U.id}}
        save {verification_id: r.id, user_id: U.id, expires_at: r.expires_at, links: r.links}
        send message: "Код: <code>{r.code}</code>. Откройте страницу и нажмите
                      «Отправить SMS» или «Позвонить»."
        send inline button "Открыть страницу" -> r.links.page_url
        send button "Я отправил" (запускает poll)

on webhook verification.verified:
    verify HMAC
    v = payload.verification
    if v.metadata.telegram_user_id != saved.user_id: reject
    if saved already bound: ignore (idempotency)
    bind U.id <-> v.phone
    send "Номер {mask(v.phone)} привязан"

on "Я отправил" from U:
    poll GET /verifications/{id} until verified/expired (не чаще 1 раза в 3 с)
```

Требования к боту:

- Работать только в личном чате; в группах код не показывать.
- Не принимать от пользователя текст «я отправил» как подтверждение — только
  статус от PhoneGate.
- Ограничить выдачу кодов: 3 в час и 10 в день на Telegram-пользователя; в интерфейсе
  бота — не больше одного активного кода на пользователя. Технически бэкенд допускает
  несколько SMS-кодов на одном номере шлюза; ограничение одного активного кода относится
  к `call`/`any` на паре «телефон + номер шлюза».
- Хранить `verification_id` и `telegram_user_id` до истечения TTL; после —
  удалять.
- Не логировать код и номер телефона целиком.
- Показывать номер в маскированном виде (`+7900***4567`) и просить подтверждение
  «Это ваш номер?» перед окончательной привязкой.
- Если номер уже привязан к другому Telegram-аккаунту — политика бота:
  отклонить или предложить отвязку (не автоматически).

## 5. Безопасность

| Риск | Мера |
|---|---|
| Подбор кода | 8 символов из 32 (≈40 бит), TTL 10 мин, одна попытка на код, rate limit |
| Утечка кода из чата | Личный чат, предупреждение «не пересылайте код», удаление сообщения после привязки |
| Пересылка `page_url`/QR | Короткий TTL, сверка `telegram_user_id`, не логировать токен, подтверждение номера |
| Чужой человек отправил SMS | Код — bearer-секрет; показывается только запросившему; подтверждение номера пользователем |
| Бот врёт о номере | Номер берётся только из подписанного вебхука/ответа API, не из сообщения пользователя |
| Чужая контактная карточка | При `request_contact` проверять `contact.user_id == from.id` |
| Подмена вебхука | HMAC-SHA256, timestamp, проверка `telegram_user_id` |
| Спам кодов | Лимит на Telegram-пользователя и арендатора; в UI один активный код, в API — лимит SMS на телефон |
| Флуд SMS на шлюз | Лимит на отправителя и номер шлюза; временная блокировка |
| Утечка API-ключа бота | Ключ только на сервере бота, не в клиенте; ротация |
| Телефон уже привязан | Проверка на стороне бота; ручная отвязка |

Важно: code-first доказывает, что отправитель SMS контролирует номер **в момент
отправки**. Он не доказывает, что этот номер «принадлежит» Telegram-аккаунту
навсегда. Для чувствительных действий (платежи, смена пароля) нужен
дополнительный фактор.

### 5.1. Уровни риска

| Сценарий | Что достаточно |
|---|---|
| Контактный номер для уведомлений | `request_contact` или code-first + подтверждение |
| Привязка номера к профилю | code-first + показ маскированного номера + подтверждение |
| Вход/восстановление доступа | `request_contact` (номер аккаунта) + code-first, либо второй фактор |
| Платежи, смена пароля | Телефон не единственный фактор: пароль, 2FA, ручная проверка |

Чем выше риск, тем важнее, чтобы код не покидал личный чат и чтобы номер
подтверждался пользователем осознанно.

## 6. UX-сообщения

Пример:

```
Чтобы привязать номер:

1. Отправьте SMS с текстом  K7M4Q9PX
   на номер  +79005550001
2. Вернитесь в этот чат и нажмите «Я отправил».

Код действует 10 минут. Не пересылайте его другим людям.
```

После успеха:

```
Готово. Номер +7900***4567 привязан к вашему аккаунту.
```

Ошибки:

- «Код истёк. Запросите новый.»
- «Не видим SMS. Проверьте номер и текст, попробуйте ещё раз.»
- «Этот номер уже привязан к другому аккаунту.»
- «Слишком много попыток. Попробуйте позже.»

## 7. Ограничения

- Пользователь должен оплатить исходящую SMS по своему тарифу.
- Задержка — интервал опроса шлюза (для авторизации рекомендуется 5 с).
- В v1 нет long polling: бот получает результат вебхуком или опросом `GET /verifications/{id}`.
- `page_url` и QR — bearer-ссылки: при пересылке получатель увидит код и сможет
  отправить SMS. Поэтому короткий TTL и обязательная сверка `telegram_user_id`.
- Номер отправителя может быть скрыт/подменён оператором; SMS-спуфинг сложнее
  звонкового, но полностью не исключён.
- В группах и каналах сценарий не работает — только личный чат.
- Бот не может написать пользователю первым: пользователь должен сам нажать Start.
- Telegram-аккаунт может быть без номера (редко) или с закрытым профилем;
  code-first это обходит, `request_contact` — нет.
- Хранение `telegram_user_id` + телефона — персональные данные; нужны согласие,
  политика конфиденциальности и срок хранения.

## 8. Чек-лист внедрения

- [ ] В боте есть личный чат и кнопка «Привязать номер».
- [ ] Вебхук Telegram защищён `secret_token`, если бот работает через вебхук.
- [ ] Бот вызывает `POST /verifications` с `mode=code_first` и своим API-ключом.
- [ ] Код генерирует PhoneGate; бот его не придумывает.
- [ ] Настроен вебхук с HMAC или polling с интервалом 3 с.
- [ ] Проверяется `metadata.telegram_user_id`.
- [ ] Есть лимиты на пользователя; несколько SMS-кодов могут сосуществовать, а
      `call`/`any` — не больше одного на пару «телефон + номер шлюза».
- [ ] Код и телефон не попадают в логи.
- [ ] Бот сохраняет `links` из ответа на создание; в `GET` их нет.
- [ ] Кнопка «Открыть страницу» ведёт на HTTPS `page_url`, а не на `sms:`/`tel:`.
- [ ] Проверены iPhone Safari, Android Chrome и Telegram WebView: SMS/звонок,
      копирование, QR и fallback «Открыть в браузере».
- [ ] Есть сценарии «истёк», «не пришло», «номер занят».
- [ ] Пользователь подтверждает маскированный номер перед привязкой.
- [ ] Есть политика отвязки и удаления данных.
