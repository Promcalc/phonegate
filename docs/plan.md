# Phonegate — план реализации

Android-приложение для телефона-шлюза: обменивается с сервером принятыми SMS и журналом
звонков, исполняет команды сервера (отправить SMS, совершить звонок) и обрабатывает
входящие звонки (автоответ, проигрывание mp3-сообщения, запись ответа абонента).

Исходное ТЗ: [tz.txt](tz.txt). API: [api/openapi.yaml](api/openapi.yaml).
Журнал принятых решений: [decisions.md](decisions.md).

## 1. Границы этапа

Входит: обмен данными, планирование и исполнение исходящих действий, обработка входящих
звонков, настройки, логи. Не входит (задел на будущее): расшифровка голосовых сообщений
в текст — в поле `text` для звонков пока всегда пустая строка.

## 2. Ключевые решения

| № | Решение |
|---|---|
| D1 | Сборка на AGP 9.1.1 с built-in Kotlin (плагин `kotlin-android` не применяется) |
| D2 | `targetSdk = 33`: обход ограничений Android 14/15/16 на старт foreground-служб |
| D3 | Автоответ: `TelecomManager.acceptRingingCall()`, фолбэк — роль «Телефон по умолчанию» |
| D4 | Голос абоненту: громкая связь + воспроизведение mp3 через микрофон |
| D5 | Запись ответа абонента: `MediaRecorder` с источником `MIC` |
| D6 | В отчёт идут только новые SMS и звонки (курсор с момента последней успешной отправки) |
| D7 | UI: Kotlin + Jetpack Compose, две вкладки |
| D8 | Авторизация: два поля (имя заголовка + значение); пустое имя — без заголовка |
| D9 | mp3 выбирается через SAF, хранится persistable-URI |
| D10 | Записи разговоров: хранить N последних, старые удалять |
| D11 | POST отправляется в каждом цикле, даже если новых данных нет |
| D12 | Ошибки сети и 4xx — копим данные и повторяем; курсор сдвигается только при успехе |
| D13 | В отчёт идут все типы звонков (входящие, пропущенные, исходящие) + поле `direction` |
| D14 | Два независимых URL: обмен (запрос+команды) и отчёт об исходящих действиях |
| D15 | Ожидание по звонкам задаётся в секундах (счёт гудков платформа не отдаёт) |
| D16 | `applicationId`/`namespace`: `ru.promcalc.phonegate` |

## 3. Целевые версии и ограничения платформы

- `minSdk = 24`, `targetSdk = 33`, `compileSdk = 36.1`; JDK 17 (toolchain 21), Gradle 9.3.1.
- Пониженный `targetSdk` нужен, чтобы служба могла стартовать из `BOOT_COMPLETED` с типом
  `microphone` и без лимита `dataSync` 6 ч/сутки. Подробнее — [decisions.md](decisions.md), D2.
- Служба объявляет типы `dataSync|microphone` и постоянное уведомление.
- Запланированные задачи исполняет сама служба, `AlarmManager` дублирует их как страховка
  (при отказе в доступе «Будильники и напоминания» используется `setAlarmClock`).
- Экран онбординга ведёт по разрешениям, спец-доступам и настройкам автозапуска прошивки.
- `usesCleartextTraffic="true"`: URL задаёт пользователь, он может быть `http://`.

## 5. Хранение данных

`Settings` (SharedPreferences, отдаётся во Flow):

| Настройка | Тип, по умолчанию |
|---|---|
| Запускать фоновый процесс при включении телефона | Bool, false |
| Фоновый процесс запущен | Bool, false |
| Интервал запросов, сек | Int, 60 (мин. 5) |
| URL обмена (приём/команды) | String |
| URL отчёта об исходящих | String (пусто — не отправлять) |
| Имя заголовка авторизации | String, `Authorization` (пусто — без авторизации) |
| Значение заголовка | String |
| Номер телефона SIM1 / SIM2 | String |
| Секунд до снятия трубки (входящий) | Int, 10 |
| Максимальная длительность записи, сек | Int, 60 (0 — не записывать) |
| Секунд до сброса (исходящий) | Int, 30 |
| mp3 для входящих, SIM1 / SIM2 | SAF-URI + путь |
| Начало сбора данных | дата-время, по умолчанию — первый запуск |
| Хранить записей разговора | Int, 20 |

Служебное состояние (тоже персистентно): `lastSuccessSyncAtMs`, `lastSmsId`, `lastCallId`,
`lastSuccessOutgoingAtMs`, `lastOutgoingId`, текущий `sync_id`.

Правила курсора:
- окно выборки: `date >= windowStart − 5 мин`, где `windowStart = max(historyStartAt, lastSuccessSyncAt)`;
- дубли отсекаются по `_id <= lastId`;
- курсор и `lastSuccess*` двигаются только после успешного POST;
- изменение «Начало сбора данных» сбрасывает курсоры на указанный момент;
- `sync_id` один и тот же для всех повторов одного окна, новый — после успешной отправки.

Задачи из ответа сервера хранятся в `files/tasks.json`, журнал исходящих действий — в
`files/outgoing.json`, логи — `files/logs/gateway-YYYY-MM-DD.log` (7 дней), записи разговоров —
`files/records/*.m4a` (N последних).

## 6. Обмен с сервером

Полное описание — [api/openapi.yaml](api/openapi.yaml).

1. **URL обмена** — `POST` отчёта (принятые SMS + весь журнал звонков с `direction`), в ответ
   приходит список SMS к отправке и звонков к совершению. Успех → сдвиг курсора и планирование
   задач; ошибка → данные копятся, повтор на следующем цикле.
2. **URL отчёта об исходящих** — `POST` журнала наших действий (отправленные SMS и совершённые
   звонки). Если адрес не задан — шаг пропускается. Обрабатывается независимо от первого URL.

## 7. Фоновая служба

- `GatewayService` — foreground, `START_STICKY`, типы `dataSync|microphone`.
- Цикл: `sync()` → пауза `intervalSeconds`; время считается по часам, а не по числу итераций.
- На время работы — `PARTIAL_WAKE_LOCK`.
- Старт/стоп только по воле пользователя; после сохранения настроек служба перезапускается.
- `BootReceiver` поднимает службу при загрузке, если включена настройка.
- При невозможности старта из фона (`ForegroundServiceStartNotAllowedException`) — запись в лог
  и уведомление с переходом в приложение.

## 8. Телефония

**Входящий звонок:** определить подписку → ждать `incomingAnswerAfterSeconds` → если звонок
сброшен, выйти; если нет mp3-файла — сбросить звонок; иначе снять трубку, включить громкую
связь, проиграть mp3, записать ответ не дольше `maxRecordSeconds` (0 — не записывать),
положить трубку, почистить старые записи. Каждый шаг — в лог.

**Исходящий звонок (команда сервера):** позвонить с нужной SIM в указанное время (просрочено —
сразу), по истечении `outgoingHangupAfterSeconds` положить трубку. Детект «абонент ответил» и
проговаривание `text` — этап с ролью «Телефон по умолчанию».

**SMS (команда сервера):** отправить с нужной SIM в указанное время (просрочено — сразу),
разбив на части, результат — в лог и в журнал исходящих.

## 9. UI

Две вкладки: «Настройки» (все поля, SAF-пикер mp3, кнопки запуска/остановки и «Отправить
сейчас», статус последней отправки) и «Логи» (фильтр, поиск, копирование, details запроса и
ответа). Плюс экран онбординга разрешений.

## 11. Риски

| Риск | План Б |
|---|---|
| `acceptRingingCall()` не работает без роли диалера | роль «Телефон по умолчанию» + `InCallService` |
| Микрофон занят модемом, запись пустая | фолбэк `AudioRecord` (`MIC` → `VOICE_RECOGNITION`), ошибка в лог |
| Прошивка убивает фон | онбординг автозапуска, `setAlarmClock` как «подниматель» |
| Старт службы с микрофоном из boot заблокирован | уведомление «откройте приложение», повышение `targetSdk` |
| Звонок с конкретной SIM | звонок с SIM по умолчанию + WARN в лог |
| Номера SIM недоступны | номера из настроек, маппинг по `simSlotIndex` |

## 12. Тестирование

Юнит-тесты (JVM): формат времени, маппинг `CallLog.Calls.TYPE` → `direction`, логика курсора,
сериализация DTO, порядок и просрочка задач, нормализация номеров при разборе ответа.
Ручной прогон на устройстве — по чек-листу из M0–M8.
